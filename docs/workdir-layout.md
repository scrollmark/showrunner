# Work directory layout (public contract)

Every `showrunner create` run materializes into a work directory
(`showrunner-*` under the system temp dir by default; the path is printed
as `WORKDIR: <path>` and emitted as a `WorkDirReady` event). The layout
below is a **public contract**: `showrunner resume`, `showrunner refine`,
`showrunner export`, and the hosted platform worker all depend on it.
Additive changes are fine; renames/removals are breaking.

```
<work_dir>/
├── showrunner.json          # run metadata + stages summary (see below)
├── plan.json                # the Plan storyboard, camelCase JSON
├── checkpoint_plan.json     # per-stage checkpoints (see schema below)
├── checkpoint_assets.json
├── checkpoint_compose.json
├── checkpoint_render.json
│
│  # faceless-explainer (Remotion render):
├── src/
│   ├── Root.tsx             # generated by compose
│   ├── scenes/<SceneId>.tsx # generated per scene by assets
│   └── tokens/preset.generated.ts
├── public/
│   ├── audio/<scene_id>.wav # TTS narration per scene
│   └── music/<track>        # staged background music (optional)
│
│  # ai-video (FFmpeg render):
├── clips/<scene_id>.mp4     # generated video clips
├── audio/<scene_id>.wav     # TTS narration per scene
├── concat.txt               # FFmpeg concat manifest (compose)
├── scene_order.txt          # scene ordering for audio mixing (compose)
│
│  # manim-explainer (Manim CE + FFmpeg render):
├── scenes/<scene_id>.py     # generated Manim Scene code per scene
├── clips/<scene_id>.mp4     # per-scene manim renders
├── audio/<scene_id>.wav     # TTS narration per scene
├── media/                   # manim's own intermediate media tree
├── concat.txt               # FFmpeg concat manifest (compose, same as ai-video)
├── scene_order.txt
│
│  # faceless-explainer + ai-video, when --captions is on:
└── captions/<scene_id>.json # word-level Caption[] per scene (README "Captions" contract)
```

## `showrunner.json`

Written at the start of a run, before the plan stage:

```json
{
  "format": "faceless-explainer",
  "aspect_ratio": "9:16",
  "style": "3b1b-dark",
  "topic": "Why do cats purr?",
  "options": {
    "aspect_ratio": "9:16",
    "voice": "af_heart",
    "speed": 1.0,
    "captions": false,
    "watermark": null,
    "parallel": false,
    "no_audio": false,
    "music": "auto",
    "music_volume": null,
    "music_seed": null
  },
  "stages": {
    "plan": "completed",
    "assets": "in_progress",
    "compose": "pending",
    "render": "pending"
  }
}
```

- `options` is the replay record: `showrunner resume` re-applies these so
  a resumed render matches the interrupted one.
- `stages` mirrors the per-stage checkpoint statuses and is refreshed on
  every checkpoint write. The individual `checkpoint_<stage>.json` files
  are the source of truth; `stages` is a convenience for hosts that want
  a single read.

## Checkpoint schema (`checkpoint_<stage>.json`)

One file per pipeline stage — `plan`, `assets`, `compose`, `render` — in
execution order. Written by `showrunner.checkpoints`.

```json
{
  "stage": "assets",
  "status": "completed",
  "started_at": "2026-07-20T18:03:11.482910+00:00",
  "completed_at": "2026-07-20T18:06:42.001523+00:00",
  "error": null,
  "outputs": {
    "assets": {"durations": {"hook": 4.2}, "has_audio": true, "width": 1080, "height": 1920}
  }
}
```

| Field | Meaning |
|-------|---------|
| `stage` | One of `plan`, `assets`, `compose`, `render`. |
| `status` | `pending`, `in_progress`, `awaiting_human`, `completed`, `failed`. A missing checkpoint file means `pending`. |
| `started_at` / `completed_at` | ISO-8601 UTC. `completed_at` is set on both `completed` and `failed`. |
| `error` | Failure message when `status == "failed"`, else `null`. |
| `outputs` | Stage outputs or pointers to them inside the work_dir. `plan` → `{"plan_file": "plan.json"}`; `assets` → the format's asset metadata dict (paths stringified); `render` → `{"output_path": "<abs mp4 path>"}`. |

`awaiting_human` is reserved for a future approval gate between plan and
assets; the pipeline does not emit it yet, but resumers must treat it as
"not completed" (the stage re-runs).

## Resume semantics

`showrunner resume <work_dir>` (or `Pipeline.run(resume_from=work_dir)`):

1. Stages whose checkpoint is `completed` are skipped. `plan` is only
   skipped when `plan.json` also exists; `render` is only skipped when
   its recorded `output_path` still exists on disk.
2. The first stage that is not `completed` (including `in_progress`
   left behind by a crash, or `failed`) re-runs from there.
3. The **assets** stage additionally resumes per-scene: existing
   narration WAVs, validated scene TSX files, and non-empty video clips
   are kept; only missing scenes are regenerated. The expensive LLM
   planner is never re-invoked when `plan` is complete.
4. Run options are replayed from `showrunner.json` (`options`), so
   explicit style/voice arguments are unnecessary — and ignored — on
   resume. `--output` may be overridden.
